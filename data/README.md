# Dataset Notes

## Source

**CMS DE-SynPUF 2010 Outpatient Claims**
- Download: [Kaggle — CMS DE-SynPUF 2010 Outpatient Claims](https://www.kaggle.com/datasets/kukulauren/cms-desynpuf-2010-outpatient-claims)
- Original source: [CMS (Centers for Medicare & Medicaid Services)](https://www.cms.gov/Research-Statistics-Data-and-Systems/Downloadable-Public-Use-Files/SynPUFs)

## Data Type

This dataset is **fully synthetic** — it was generated by CMS to mimic real Medicare claims patterns without exposing any real patient data. There are no privacy concerns or data usage restrictions for research purposes.

## Size

| Stage | Records |
|---|---|
| Raw download | ~2.3 million rows (multiple beneficiary files) |
| After cleaning & filtering (outpatient only) | ~175,000 claims |
| Train split (80%) | ~140,000 claims |
| Test split (20%, with 3% anomaly injection) | ~35,000 claims |

## How to Obtain the Data

1. Go to the [Kaggle dataset page](https://www.kaggle.com/datasets/kukulauren/cms-desynpuf-2010-outpatient-claims)
2. Download the CSV files
3. Place the main claims file in the project root directory
4. The notebooks will handle loading and path references

> **Note:** The dataset file is not included in this repository due to file size. It must be downloaded separately from Kaggle.

## Engineered Features (14 total)

All features are derived from the raw claim fields. No external data sources are used.

| # | Feature | Category | Description |
|---|---|---|---|
| 1 | `log_payment` | Monetary | Log-transformed total claim payment |
| 2 | `reimbursement_ratio` | Monetary | Medicare reimbursement / total payment |
| 3 | `deductible_amount` | Monetary | Beneficiary deductible paid |
| 4 | `claim_duration_days` | Temporal | Days between claim start and end date |
| 5 | `admission_month` | Temporal | Month of service (seasonality signal) |
| 6 | `day_of_week` | Temporal | Day of week of claim submission |
| 7 | `procedure_code_count` | Utilization | Number of distinct procedure codes on claim |
| 8 | `diagnosis_code_count` | Utilization | Number of distinct diagnosis codes on claim |
| 9 | `claim_frequency` | Utilization | Number of claims per beneficiary in dataset |
| 10 | `provider_anomaly_rate` | Provider-level | Fraction of provider's claims flagged as anomalous |
| 11 | `claims_per_provider` | Provider-level | Total claims volume per provider |
| 12 | `avg_payment_per_provider` | Provider-level | Mean payment across all of provider's claims |
| 13 | `inpatient_flag` | Structural | Binary: inpatient vs outpatient claim |
| 14 | `primary_diagnosis_group` | Structural | Encoded primary ICD diagnosis category |

## Anomaly Injection Protocol

For the semi-synthetic evaluation (Notebook 1), synthetic anomalies are injected into the **test set only** at a **3% contamination rate**. Anomaly types injected:

- **Inflated payments:** Payment values set to 5-10x the provider's normal average
- **Unusual code combinations:** Rare procedure/diagnosis code pairings not seen in training
- **High-frequency short-duration claims:** Abnormally high claim count with very short duration

The training set remains clean to simulate a realistic unsupervised detection scenario.
